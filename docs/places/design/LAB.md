## Run it

```
JSC=/System/Library/Frameworks/JavaScriptCore.framework/Versions/Current/Helpers/jsc
"$JSC" my-sweep.js
```

and in `my-sweep.js`, from any folder:

```js
load('<scratch>/places/engine-map/lab.js');
var PLACE = { S: 2, CUSTOM: [1, 1, 0, 1, 1] };
Lab.sweep(Lab.seeds(1, 30), PLACE, ['custom', 'always', 'never', 'careful', 'careful+grab'], 200);
```

`lab.js` sets `globalThis.Lab` and `globalThis.AfterYou` (the prototype engine, also at `Lab.AY`). Every function prints a table and a `[lab]` timing line, and returns the same numbers as data; set `Lab.quiet = true` to silence printing.

## A place is an overrides object

Pass it wherever a function takes `overrides`. Anything left out is the valley's value. `null` means the valley.

| Key | Dial | Valley | Meaning |
|---|---|---|---|
| `B`, `C` | D1 | 3, 1 | A hand that arrives is worth `B` to the house it reaches and costs the sender `C`. |
| `S` | D1 | 0 | Added to each side on a day both hands arrived. |
| `H` | D1 | 0 | Taken from each side on a day neither hand arrived. |
| `FOG` | D2 | 0.04 | The rate of the luck, whatever its kind. |
| `LUCK_KIND` | D2 | `'lost'` | `'lost'`: the hand is turned back, costs and pays nothing, the sender knows. `'unseen'`: it arrives and pays, but the receiver and every witness saw none. `'phantom'`: nothing was sent or paid, but a hand was seen. |
| `CHARTER` | D3 | `'holds'` | Lab only. `'breaks'` reads the same counts the other way: mark = baselinePct - holdsPct. |
| `CUSTOM` | D4 | `[1,1,0,1,0]` | The custom of the place, five chances in the order new, both helped, left short, left them short, both stayed home. Kin's founding way, the heir's untested ways, the reference Life (need) and the baseline use it. Keep it to 0s and 1s (see Cautions). |
| `TURNOVER` | D5 | `null` | `{ days: [5, 9], kinds: ['taker', 'wary'] }`: in the night before one of those days a stranger of one of those kinds takes over one non-kin neighbour's holding. |
| `ARRIVALS` | D5 | 1 | Newcomers in the Afterwards (0 = none), each in its own season within `ARRIVE_FROM..ARRIVE_TO` (valley 4..12). |
| `NEWCOMER` | D5/D9 | `null` | The kind that arrives: five entries, each a number or `[low, high]`. `null` is the valley's taker. |
| `STOCK` | D6 | `null` | `{ start: 1, min: 0.5, max: 1.5, delta: [d0, d1, d2] }`: a level on each tie. A hand is worth `B x level`; then the level moves by `delta[hands that arrived on the tie today]`. Use eighths (0.125) so the store stays exact. |
| `SIDES` | D7 | `null` | Eight labels, house 0 first, e.g. `[0,0,0,0,1,1,1,1]`: a house that looks round picks its model on its own side only. |
| `FOUNDERS` | D9 | `null` | `{ near: [three entries for the non-kin seats: a kind or a list to draw from], far: [pool of three or more], kinds: { name: [five entries] } }`. Built-in kinds: `firm`, `soft`, `taker`, `wary`, `steady`. |
| `FLOW_KIND` | charter | `'hands'` | What "holds" counts: `'hands'` (hands arrived), `'ties'` (share of tie-days with at least one hand), `'both'` (share with both). |
| `HOLD_LINE` | charter | 0.5 | Late flow at which a future holds. |
| `NEED_PIVOT`, `NEED_WEIGHT`, `MARGIN` | need | 59, 0.5, 6 | `need = max(custom's purse + 1, round(PIVOT + WEIGHT x (custom's purse - PIVOT) + MARGIN))`. The pivot is tuned to the valley; use `Lab.tuneNeed` for a place. |
| `K`, `MUT`, `R_LIFE`, `R_AFTER` | schooling | 0.5, 0.05, 1, 1 | The valley's own tunables, unchanged. `K` is in measures per tie per day, so stakes that widen incomes sharpen copying. |
| `RANGE_WAYS` | range | `null` | The plain ways behind `verdict().range`. The custom is appended when missing. |

Not in the prototype (described and costed in `ENGINE-MAP.md`): D5 an end not known in advance, D7 copying the many, D8 sight (totals only, a day late).

## Ways of playing

A `way` argument is any of:

- five chances, `[1, 1, 0.5, 1, 0]`, played with keyed draws;
- a name: `'custom'` (the place's `CUSTOM`), `'always'`, `'never'`, `'unless-short'` (`[1,1,0,1,1]`), `'mirror'` (`[1,1,0,1,0]` whatever the custom is), `'bully'` (stays home against a neighbour until two hands have come from it, then does as it did yesterday), `'forgiving'` and `'careful'` and `'cold'` (the valley harness's policies, screen information only);
- any of those with a suffix: `'+grab'` (stays home against all on day 12), `'+grab2'`, `'+grab3'`, `'+give'` (sends to all on day 12), `'+grab-if-decides'` (takes on day 12 exactly when that is what fills the store, and no more than it takes; uses the place's stakes);
- a maker `function (ctx) { return function (nb, T) { return true; }; }` with `ctx = { seed, params, archetypes, fog }`, `T = today(life)`, `nb` one of `T.neighbours`. The valley harness's policies fit as they are.

## Functions

```
Lab.seeds(a, b)                                  -> [a .. b]
Lab.playLife(seed, overrides, way, script?)      -> { life, choices, days, name }
Lab.measure(seeds, overrides, way, futures)      -> { rows: [per seed], mean: {...} }
Lab.sweep(seeds, overrides, ways, futures)       -> { table: [one mean per way], spread, baseline, perSeed }
Lab.purses(seeds, overrides, ways)               -> the store side only, no futures (2000 seeds x 5 ways in 1 s)
Lab.tuneNeed(seeds, overrides, way, targetPct, { also: [ways] })
                                                 -> { NEED_PIVOT, NEED_WEIGHT, MARGIN, keptPct, also, overrides }
Lab.bestWay(seeds, overrides, { values: [0, 0.5, 1], futures: 100, top: 5 })
                                                 -> { byMark, byPurse, byKept, named, trivial, all }
Lab.carried(seeds, overrides, ways?, futures)    -> ways carried by heir and kin (the valley's G3 / G4 method)
Lab.pull(seeds, overrides, way, day, futures?)   -> what sending to all four instead of staying home on that day is worth
Lab.timing(overrides?)                           -> seconds per 1000 futures, per 1000 Lives, per full verdict
```

`measure().rows[i]` = `{ seed, purse, need, oldPurse, kept, holdsPct, baselinePct, mark, markSE, lateFlow, lastDay, seal }`. `holdsPct` and `baselinePct` always count futures in which the place holds. `mark` is the charter's mark. `seal` is the engine's own rule (`verdict().seal`), with one mirrored clause under `CHARTER: 'breaks'` (`markBoughtOnLastDay`). `lastDay` is the engine's last-day replay, or `null`.

Columns of the sweep table:

| Column | Meaning |
|---|---|
| purse, need | Mean store and mean need over the seeds. |
| kept% | Share of Lives with store at least the need. |
| holds%, base% | Mean share of futures that hold: with this way lived and left, and with the custom lived and left. |
| mark, +-sem | Mean charter mark over the seeds, and the standard error of that mean across seeds. A difference between two ways smaller than about twice the larger sem is not established. |
| seal% | Share of Lives that earn the seal under the engine's rule. |
| grab% | Share of Lives with a last-day entry: the house stayed home on day 12 against a neighbour after both had helped. |
| bought% | Share of Lives whose house was kept only by that (the seal is withheld). |

The two lines under a sweep: the spread is, within each seed, highest minus lowest holds% among the ways listed (H5 asks for 25 points on most seeds); the baseline line is the valley's "not a lottery" gate (within 15..85 on most seeds).

## Sizing a run

Measured on this machine (`Lab.timing()`): about 0.05 s per 1000 futures of one row, 0.2 s per 1000 Lives without futures, 0.9 s for one full verdict (2000 + 2000 futures and 24 rows of 1000).

- `measure`: 2 rows per Life, 3 when there is a last-day entry. 30 seeds x 200 futures is about 0.5 s per way.
- `sweep`: that, times the number of ways. 9 ways x 30 seeds x 200 futures: 4.6 s.
- `bestWay`: grid x seeds x futures, plus one baseline per seed. 243 ways x 6 seeds x 60 futures: 3.8 s (measured). 243 x 20 x 100: about 25 s (an estimate from the per-future time, not run).
- `purses`, `tuneNeed`: no futures. Thousands of seeds are cheap.
- With 200 futures a single Life's mark has a standard error of about 3 points; the mean over 30 seeds has the sem printed in the table (about 2). Use 100 or more seeds before quoting a difference of a few points.

How to read it:

- `custom` keeps the house in 0% of Lives and has a mark of exactly 0: it is the reference Life itself. The need is by construction above what the custom earns.
- `careful` (a competent house using only what the screen shows) keeps the house in 30% of these 30 Lives and 39.3% of 2000, with a mark near +10. `careful+grab` keeps it in 75 to 80% and gives up about 7 points of mark; 43% of its Lives are kept only by the last day's taking and are refused the seal. That is the valley's trade. The valley harness, on 6000 seeds for the store and 120 for the mark, has `careful` at 40.0% and +10.2 and its last-day version at 74.6% and +1.2: the same picture, and the difference in the grab's mark (+3.2 here) is inside the noise of 30 seeds.
- `pull day 3`: staying home against all four on day 3 gains 4.0 measures that day and loses 18.0 over the days after. `pull day 12`: the same act on the last day gains 3.8 and loses nothing. That asymmetry is the temptation.
- `bestWay`: the best five-number way by mark is not the best by purse, and neither is all-send or all-stay.

## Cautions

1. **The custom never keeps the house.** `need >= custom's purse + 1` always (checked on 140 Lives across 14 settings). H5's "an honest follower keeps the house 35 to 65 percent of the time" has to be read against a competent honest way such as `careful` or `forgiving`, not against `custom`.
2. **`careful` and `forgiving` are valley policies.** They forgive and repair in ways tuned to the valley's founders. In a place with other stakes write the place's own competent way as a maker function before quoting a kept%.
3. **Keep `CUSTOM` to 0s and 1s.** A middling chance works (the reference Life then draws with its own keyed coin) but the custom's own Life no longer has a mark of exactly 0 (up to 2.5 points at 80 futures), because an heir carries lived tallies and the baseline heir carries the custom itself.
4. **`tuneNeed` plays each Life once.** That is sound for every way except `'+grab-if-decides'`, which reads the need. Run a sweep with the returned `overrides` to see that way.
5. **`CHARTER: 'breaks'` only re-reads counts.** The engine's range, what-ifs and wording are not inverted. Under it a last-day grab serves both the store and the mark; the lab's seal adds the mirrored clause, the engine has none (see `ENGINE-MAP.md` D3).
6. **Under `'unseen'` and `'phantom'`** the `they` a policy reads is what was seen. `results[i].theyArrived` and `.seenByThem` are the truth and are internal. The store still moves by what really arrived, so a page that prints the day's income gives the truth away.
